Getting started / Overview

What is Mentat?

One interface for multiple AI coding agents — Claude Code and Codex running in parallel across isolated git worktrees, with real-time status for every session.

The Problem

Modern AI-assisted development means running multiple agents simultaneously — different features, different branches, different agents. But there's no unified place to manage this:

  • Multiple scattered terminal windows — no visibility into what each agent is actually doing
  • Switching branches requires stashing or committing, even mid-task
  • Closing a terminal loses the entire AI conversation context
  • Claude Code and Codex live in completely separate setups with no shared view
The Solution

Mentat is an open-source Electron desktop app that brings all of this into one window. It uses git worktrees to keep each branch in its own isolated directory — so you can have multiple branches open at once, each with its own terminal and AI session, with zero context-switching cost.

What Mentat gives you

⊞

◉

See instantly if each agent is thinking, working, waiting, or idle.

⧉

◫

Getting started / Quickstart

Quickstart

Get Mentat running in four steps. Takes about five minutes.

Before you begin

You need Claude Code CLI and/or Codex CLI already installed and authenticated. Mentat integrates with these tools but does not replace them.

1
Install Mentat

Download the pre-built binary for your platform from the GitHub Releases page and run it — no installation required.

PlatformFile
WindowsMentat-portable.exe
LinuxMentat.AppImage
macOSMentat.dmg
bash
git clone https://github.com/demovolt/Mentat.git
cd Mentat
npm install && npm run build && npm run package

The packaged output appears in the release/ directory.

2
Install the hook script

Mentat ships a small shell script that Claude Code and Codex call at lifecycle events to report status. Copy it once — it then works across all your projects automatically.

Hook scripts are bundled inside the app at resources/app/script/, or at script/ when building from source.

bash
cp /path/to/Mentat/script/mentat-hook.sh ~/.claude/mentat-hook.sh
chmod +x ~/.claude/mentat-hook.sh
powershell
Copy-Item "C:\path\to\Mentat\resources\app\script\mentat-hook.ps1" `
  "$env:USERPROFILE\.claude\mentat-hook.ps1"
bash
cp /path/to/Mentat/script/mentat-hook.sh ~/.codex/mentat-hook.sh
chmod +x ~/.codex/mentat-hook.sh
powershell
Copy-Item "C:\path\to\Mentat\resources\app\script\mentat-hook.ps1" `
  "$env:USERPROFILE\.codex\mentat-hook.ps1"
Safe to install globally

The script exits immediately when MENTAT_TERM_ID is not set, so it does nothing outside Mentat terminals.

3
Register hooks

Tell Claude Code and Codex to call the script at each lifecycle event. Ready-to-use config files are included in the app.

Merge the following into ~/.claude/settings.json. If the file already has a hooks block, add these entries to it — don't replace the whole file.

json
{
  "hooks": {
    "SessionStart":    [{ "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh session_start" }] }],
    "SessionEnd":      [{ "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh session_stop" }] }],
    "UserPromptSubmit":[{ "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh thinking" }] }],
    "PreToolUse": [
      { "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh working" }] },
      { "matcher": "AskUserQuestion", "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh waiting" }] },
      { "matcher": "Agent",           "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh agent_start" }] }
    ],
    "PostToolUse":     [{ "matcher": "Agent", "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh agent_stop" }] }],
    "Notification":    [{ "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh waiting" }] }],
    "Stop":            [{ "hooks": [{ "type": "command", "command": "bash ~/.claude/mentat-hook.sh idle" }] }]
  }
}

Same structure, but replace each command with the PowerShell form. Substitute PATH_TO_CLAUDE with your full .claude path (e.g. C:/Users/User/.claude).

json — command example
"command": "powershell -ExecutionPolicy Bypass -File PATH_TO_CLAUDE/mentat-hook.ps1 session_start"

See script/claude-settings-windows.json in the app for the complete ready-to-use config.

Create or update ~/.codex/hooks.json:

json
{
  "description": "mentat",
  "hooks": {
    "session_start":      [{ "command": "bash ~/.codex/mentat-hook.sh session_start" }],
    "session_end":        [{ "command": "bash ~/.codex/mentat-hook.sh session_stop" }],
    "user_prompt_submit": [{ "command": "bash ~/.codex/mentat-hook.sh thinking" }],
    "pre_tool_use":       [{ "command": "bash ~/.codex/mentat-hook.sh working" }],
    "post_tool_use":      [{ "command": "bash ~/.codex/mentat-hook.sh thinking" }],
    "stop":               [{ "command": "bash ~/.codex/mentat-hook.sh idle" }],
    "subagent_start":     [{ "command": "bash ~/.codex/mentat-hook.sh agent_start" }],
    "subagent_stop":      [{ "command": "bash ~/.codex/mentat-hook.sh agent_stop" }]
  }
}

Same structure, replace each command with the PowerShell form. Replace PATH_TO_CODEX with your .codex folder path.

json — command example
"command": "powershell -ExecutionPolicy Bypass -File PATH_TO_CODEX/mentat-hook.ps1 session_start"

See script/codex-hooks-windows.json in the app for the full config.

4
Launch Mentat
  1. Start the app (Mentat.exe, Mentat.AppImage, or the macOS app)
  2. Open Settings → Connection — confirm the status server is green and hook scripts show ✓
  3. Click + in the toolbar to add a Git repository
  4. Select a worktree and click the Claude or Codex button to open an AI terminal

Troubleshooting

Status indicators not updating

Open Settings → Connection and check that the status server is running and hook scripts are marked ✓. If a script shows ✗, repeat Step 2 — the file is missing from the expected location.

Windows + WSL: hooks not reaching Mentat

powershell
netsh advfirewall firewall add rule name="Mentat Status" dir=in action=allow protocol=TCP localport=27182

Restart Mentat after adding the rule.

Port 27182 conflict

Mentat automatically tries 27183–27191 if 27182 is taken. The active port is shown in Settings → Connection.

bash
# Linux / WSL
lsof -i :27182

# Windows PowerShell
netstat -ano | findstr :27182
Guides / How to Use

How to Use

A step-by-step walkthrough of the core Mentat workflow.

Add a repository

Click the + button in the toolbar at the top of the sidebar. Select the root folder of any git repository. Mentat reads the git tree and discovers all existing worktrees automatically — they appear as children of the repository in the sidebar.

Add a worktree

Right-click a repository in the sidebar and choose New worktree. In the dialog, pick an existing branch or type a new branch name to create one. Mentat creates a fully isolated directory for that branch on disk — completely independent of your main working directory.

What is a worktree?

A git worktree is a separate checkout of a repository branch. Each branch lives in its own folder — you can edit, build, and run them independently with no stashing or committing needed to switch.

Open a terminal

Click a worktree to select it, then click the Shell button. A terminal opens already cd'd into the correct directory. Use the + in the terminal tab bar to open additional shell tabs for the same worktree.

Open an AI session

Click the Claude or Codex button inside any worktree. Mentat spawns the CLI in the correct directory and automatically passes --resume if a previous session exists for this worktree — the conversation continues from where it stopped.

Status indicators

While an AI is active, a live badge appears next to the terminal in the sidebar:

Thinking
Processing your prompt, between tool calls
Working
Actively executing a tool — reading, writing, running
Waiting
Waiting for your input or a confirmation
Idle
Task complete, ready for the next prompt

Session resume

Mentat stores the Claude session ID per worktree. The next time you open an AI terminal for the same worktree, it passes --resume <sessionId> automatically. The AI remembers the full prior conversation.

Per-worktree context

Session IDs are isolated per worktree. Switching to a different branch always gives you the correct conversation context for that branch, with no cross-contamination.

Subagent tracking

When Claude Code dispatches a managed subagent via the Agent tool, Mentat shows each running agent under the terminal entry in the sidebar, with its description. You can see at a glance how many parallel agents are active and what each one is doing.

Guides / How it Works

How it Works

The technical architecture behind Mentat's real-time AI status tracking.

Architecture overview

Mentat does not call the Claude or Codex API. Instead, it integrates at the CLI lifecycle level: a hook script registered with the CLI fires at specific events and POSTs a status update to a local HTTP server inside Mentat, which then pushes the update to the React UI via Electron IPC.

Claude Code / Codex CLI
Running inside node-pty (PTY process)
Lifecycle event fires (PreToolUse, Stop…)
mentat-hook.sh / .ps1
~/.claude/ or ~/.codex/ — called by the CLI
HTTP POST /status { termId, status }
Status Server :27182
HTTP server in Electron main process
Updates in-memory Map → IPC → renderer
React UI (App.jsx)
Re-renders sidebar status badges

Components

Electron main process

Manages the app lifecycle (electron/main.js). On startup it creates the BrowserWindow, starts the status server on port 27182 (falling back to 27183–27191), and registers IPC handlers for git operations and terminal management. A ptyProcesses Map tracks every open terminal tab.

Status server

A plain HTTP server (electron/status-server.js) that accepts POST requests from hook scripts and updates shared in-memory state in electron/terminal-state.js.

EndpointPayloadPurpose
POST /status{ termId, status, sessionId? }Update terminal status or record session start/stop
POST /agent{ termId, agentId, event, description? }Track subagent lifecycle (start / stop)

Terminal spawning

When you open a terminal (electron/ipc/pty.js), Mentat spawns a shell or AI CLI using node-pty and injects three environment variables before the process starts:

VariableValuePurpose
MENTAT_TERM_IDterm-3-1720000000Identifies which terminal tab this status belongs to
MENTAT_STATUS_PORT27182Port of the local status server
MENTAT_STATUS_HOST127.0.0.1 or WSL host IPAddress of the status server — auto-resolved for WSL

React UI

The renderer (src/App.jsx) subscribes to three IPC events:

  • worktree:status-changed — updates the status badge for a terminal tab
  • worktree:agent-changed — updates the subagent list in the sidebar
  • session:id-updated — stores the session ID for the next --resume

WSL bridge

On Windows, Electron runs natively while terminals may run inside WSL. Mentat resolves the Windows host IP from /etc/resolv.conf inside WSL and injects it as MENTAT_STATUS_HOST, forwarded into the WSL environment via WSLENV.

Git operations

All git operations go through electron/ipc/git.js, which calls the system git CLI via child_process. No git library — just the real CLI.

State persistence

In-memory state (statuses, active agents) resets on app restart. Workspace config and session IDs are persisted to config.json and state.json on disk — this is what powers session resume across restarts.

Guides / Connection to Chat AI

Connection to Chat AI

How Mentat integrates with Claude Code and Codex — at the CLI level, without calling any cloud API.

Key distinction

Mentat does not call the Anthropic API or OpenAI API. It integrates with the locally installed CLI tools — claude and codex — the same programs you run in a regular terminal.

Hook-based integration

Both Claude Code and Codex support a hooks system: you register shell commands that the CLI executes at specific lifecycle points. Mentat uses this to receive real-time status updates without any polling.

When you register the Mentat hook script, the CLI calls it automatically at each event:

Hook eventCLI triggerMentat status
SessionStart / session_startCLI session begins; stdin carries session_idSession ID stored for resume
UserPromptSubmit / user_prompt_submitUser sends a prompt● Thinking
PreToolUse / pre_tool_useAI is about to execute a tool● Working
AskUserQuestion matcherAI asks the user a question● Waiting
NotificationCLI waiting for confirmation● Waiting
Stop / stopAI finished the current task● Idle
SessionEnd / session_endCLI process exitedSession cleared
Agent / subagent_startA subagent is dispatchedAgent listed in sidebar
PostToolUse / subagent_stopSubagent completedAgent removed from sidebar

Session resume in detail

Claude Code assigns a unique session_id to each conversation. When the session_start hook fires, the hook script reads this ID from stdin JSON and POSTs it to Mentat's status server, which stores it keyed to the worktree.

The next time you open an AI terminal for the same worktree, Mentat automatically passes:

shell
claude --resume <sessionId>

The conversation continues exactly where it stopped — the AI remembers prior context, file changes, and messages.

Subagent tracking

When Claude Code uses the Agent tool to spawn a managed subagent, the PreToolUse hook fires with the agent description in the stdin JSON payload. The hook POSTs to /agent:

json — POST /agent
{
  "termId": "term-3-1720000000",
  "agentId": "toolu_01XYZ...",
  "event": "start",
  "description": "Search for usages of deprecated API"
}

When PostToolUse fires for the same agentId, the agent is removed from the sidebar list. This gives you a real-time view of all running agents across all worktrees.

Environment variables

VariableExamplePurpose
MENTAT_TERM_ID term-3-1720000000 Identifies which terminal tab this status belongs to. Sent with every POST.
MENTAT_STATUS_PORT 27182 Port of the status server (dynamically assigned, usually 27182).
MENTAT_STATUS_HOST 127.0.0.1 Address of the status server. On Windows + WSL, automatically set to the Windows-side host IP.

When MENTAT_TERM_ID is absent (any terminal not created by Mentat), the hook exits immediately at line 2 — safe to install globally.

Why no API?

  • No separate authentication — you log in to Claude/Codex once through the CLI; Mentat inherits that automatically
  • Zero latency overhead — status updates are fire-and-forget HTTP POSTs to localhost, not cloud round-trips
  • Full CLI feature parity — every Claude Code or Codex capability (MCP servers, tool use, file context) works exactly as in a normal terminal, because it is a normal terminal
  • Works offline — once the CLI is authenticated, Mentat works without any additional network access
